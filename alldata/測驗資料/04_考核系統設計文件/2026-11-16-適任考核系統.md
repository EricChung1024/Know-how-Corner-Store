# 適任考核系統 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做一個員工／主管雙身分的適任考核網站：員工分階段考試、看成績與錯誤類型、用錯題區檢討；主管看全員成績與錯誤類型。

**Architecture:** 靜態前端（純 HTML／JS，無建置工具）放 GitHub Pages，用 `supabase-js` 連 Supabase（Auth＋Postgres＋RLS＋RPC）。題庫與標準答案只在資料庫，員工只能經 RPC 取題、交卷後才拿到答案。題庫由本機 Python 腳本從總表 xlsx 與舊題庫 CSV 產生。

**Tech Stack:** HTML/JS（ES modules）、`@supabase/supabase-js@2.45.4`（CDN）、Supabase Postgres／RLS／RPC（plpgsql）、Python 3.13 標準庫（unittest、zipfile、csv）、Node 22（`node --test`，僅測純函式）。

**Spec:** `docs/superpowers/specs/2026-11-16-適任考核系統-design.md`

## Global Constraints

- 前端只出現 Supabase URL 與 anon key；任何檔案不得出現 service role 金鑰；`tools/` 與 `supabase/seed.sql`（含答案）不得進入 `site/`。
- 階段：1–9 為總表各章，`0` 為「綜合適任考核」。各階段抽最多 10 題；綜合抽 30 題；選項順序每次打亂。
- 及格 80 分；可重考；每次都記錄。
- 計分：選擇題（含是非）80%、情境簡答 20%；若該卷沒有簡答題，選擇題 100%；沒有選擇題則簡答 100%。
- 情境簡答：員工先作答，交卷後才看到參考答案與得分點，逐項勾選自評；題分＝勾選數 ÷ 得分點數。
- 錯題區：答錯（或簡答得分 < 1）自動收進；重練只含選擇題／是非；連續答對 2 次 → `mastered`；重練不計入 attempts。
- 出題只用總表狀態為「現行」的規則；「已失效」只能當干擾選項來源，不得是正確答案。
- 舊題一律 `source='legacy'`、`reviewed=false`；未審核題不進綜合考核。
- 角色：`employee`／`supervisor`；`profiles.role` 預設 `employee`。
- 外觀沿用既有網站：Cubic 11 字體（`AI專屬客服測驗/網站/Cubic_11.woff2`）。
- 所有使用者可見文字用繁體中文。Git commit 訊息用繁體中文，結尾加 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`。
- 資料全為虛構。

## Review Focus

1. 員工直接 `select` `questions` 表：必須被拒絕或回空（答案不外洩）。
2. 同一份 attempt 重複交卷或重複自評：第二次必須被拒絕，分數不變。
3. 員工讀別人的 attempts／wrong_book：回空；主管全部可讀。
4. 題庫不足 10 題或某階段 0 題：前者全抽、後者回明確錯誤，不得白畫面。
5. 簡答空白、得分點全沒勾、或該卷沒有簡答題：不得除以零，分數合理（空白＝0 分，無簡答則 MCQ 100%）。
6. 新註冊 Auth 使用者尚無 profile：自動建為 `employee`，不能自己升成主管。

### Task 4: 資料表、觸發器、RLS

  - `attempts(id uuid pk default gen_random_uuid(), user_id uuid, stage int check 0..9, question_ids jsonb, status text check in ('in_progress','pending_selfcheck','done'), score numeric, passed bool, started_at, submitted_at)`

### Task 5: 考試 RPC（抽題、交卷、自評）

**Files:** Create `適任考核系統/supabase/003_exam_rpc.sql`；Test `適任考核系統/supabase/tests/t_exam.sql`

**Interfaces:**
- Consumes: Task 4 資料表。
- Produces（皆 `security definer`，`set search_path = public`，限 `authenticated`）：
  - `start_exam(p_stage int) returns jsonb` → `{"attempt_id": uuid, "stage": int, "questions": [{"id","qtype","stem","options"}]}`。階段 1–9 取該章最多 10 題（選擇／是非優先，簡答至多 2 題）；階段 0 取最多 30 題且只取 `reviewed=true`。選項順序打亂，打亂後的順序存在 `attempts.question_ids`（含每題 `perm`），以便評分還原。該階段 0 題 → `raise exception 'NO_QUESTIONS'`。
  - `submit_exam(p_attempt uuid, p_answers jsonb) returns jsonb`。`p_answers` 為 `[{"question_id","choice"?:int,"text"?:string}]`。檢查：attempt 屬於 `auth.uid()` 且 `status='in_progress'`，否則 `raise exception 'ATTEMPT_CLOSED'`。評選擇題（還原 perm 後比對）；寫 `attempt_answers`；答錯的題記 `error_type`（`選項對應的 option_errors` 優先，否則題目的 `error_type`）並 upsert `wrong_book`（`wrong_count+1, streak=0, status='open'`）。若本卷有簡答題 → `status='pending_selfcheck'`，回傳 `{status, mcq_items:[…含 correct_index、explanation], short_items:[{question_id, reference_answer, rubric}]}`；否則直接結算（`status='done'`）並回傳 `{status:'done', score, passed, items}`。
  - `submit_selfcheck(p_attempt uuid, p_checks jsonb) returns jsonb`。`p_checks` 為 `[{"question_id","checked":[int,…]}]`（得分點 index）。僅 `pending_selfcheck` 可呼叫，否則 `raise exception 'ATTEMPT_CLOSED'`。題分＝勾選數÷得分點數；< 1 者記 `error_type=key_error`／題目 error_type 並 upsert `wrong_book`；結算並回傳 `{status:'done', score, passed, items}`。
  - 分數公式：`100 × (0.8×mcq_ratio + 0.2×short_ratio)`；某類題數為 0 時，另一類為 100%；`passed = score >= 80`；四捨五入到小數 1 位。

- [ ] **Step 1: 寫 `t_exam.sql`**（含 seed 小樣：階段 2 有 3 題選擇＋1 題簡答；階段 9 無題）：`start_exam(2)` 回傳的 JSON 不含 `correct_index`／`explanation`；`start_exam(9)` raise `NO_QUESTIONS`；全對＋簡答全勾 → 分數 100、`passed`；全錯 → 0 且 `wrong_book` 有 3 筆 `open`；簡答空白字串＋不勾 → 該題 0 分且不報錯；同一 attempt 第二次 `submit_exam` raise `ATTEMPT_CLOSED`；沒有簡答題的階段 → 一次 `submit_exam` 即 `done`；階段 0 不抽 `reviewed=false` 的題；打亂選項後仍能正確評分（對同一題連跑 20 次，答對的選項 index 永遠被判對）。
- [ ] **Step 2: 先跑確認失敗。** **Step 3: 實作三個 RPC。** **Step 4: 跑 `t_exam.sql` 確認通過。**
- [ ] **Step 5: Commit。**

### Task 6: 錯題區與主管 RPC

**Files:** Create `適任考核系統/supabase/004_review_rpc.sql`；Test `適任考核系統/supabase/tests/t_review.sql`

**Interfaces:**
- Produces：
  - `list_wrong(p_stage int default null, p_error_type text default null, p_status text default null) returns jsonb`：本人的錯題，每筆含題幹、選項、**正確答案與解析**（員工已答錯過才可見）、我最後作答、`wrong_count`、`status`、`note`、`error_type`。
  - `start_practice(p_limit int default 10) returns jsonb`：只取 `status='open'` 的選擇／是非錯題；無題 → `raise exception 'NO_WRONG'`；回傳 `{"practice_id": uuid, "questions": […同 start_exam]}`（打亂規則同 Task 5；practice 的 perm 暫存在 `attempts` 以外的表 `practice_runs(id, user_id, question_ids jsonb, closed bool)`，本任務一併建立）。
  - `submit_practice(p_practice uuid, p_answers jsonb) returns jsonb`：答對 `streak+1`，≥ 2 → `mastered`；答錯 `streak=0, wrong_count+1`。不寫 attempts。重複提交 raise `ATTEMPT_CLOSED`。
  - `set_wrong_note(p_question text, p_note text) returns void`、`set_wrong_status(p_question text, p_status text) returns void`（只能改自己的；改回 `open` 時 `streak=0`）。
  - 主管專用（非主管 raise `FORBIDDEN`）：`adjust_short_score(p_attempt uuid, p_question text, p_points numeric) returns jsonb`（0–1，改後重算該 attempt 分數與 `passed`）、`set_reviewed(p_ids text[], p_reviewed bool) returns int`、`list_questions_for_review(p_stage int default null, p_reviewed bool default null) returns jsonb`（主管看題庫含答案的唯一管道）。
