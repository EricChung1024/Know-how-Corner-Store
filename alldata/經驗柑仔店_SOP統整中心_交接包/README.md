# 經驗柑仔店 Know-how Corner Store｜SOP 統整中心交接包

- **網頁名稱：** 經驗柑仔店（英文 Know-how Corner Store），給各企業通用的 AI 新人學習網頁
- **GitHub repo 建議名稱：** `knowhow-corner-store`（網址會是 `https://帳號.github.io/knowhow-corner-store/`）
- **更新日期：** 2026/11/17
- **負責：** 婉萱（模擬 SOP 資料統整）
- **專題：** 企業專屬 AI 教育專員（青年AI實戰養成班）
- **線上示範：** https://claude.ai/artifact/2huwK9DLjFGPs46i8END2m（拿到連結的人都能開）

範例公司「好物集」（電商客服）只是用來示範，好物集本身和裡面的人名、訂單、數字都是虛構的。網頁本身不限產業，換一套資料就能用在其他企業。

這包是經驗柑仔店裡「SOP 統整」這一段，放了三樣東西，方便和組員後續的「問答、測驗、評分」整合成完整的經驗柑仔店：

- 做好的「SOP 統整中心」網頁
- 網頁的原始程式碼
- 上次的「統整模擬資料包 v3」（原封不動）

## 三、示範流程（約 3 分鐘）

**示範帳號（密碼隨便打）**

- 主管：`peishan`（林佩珊，資深客服專員）
- 新人：`youting`（陳宥廷）

也可以直接按「帶入示範帳號」。

**流程**

1. **主管登入。** 第一次使用時還沒有任何版本，所以「主管版 SOP」是鎖住的。
2. **第 1 格｜匯入資料：** 按「載入示範資料（9 個檔）」→「開始統整」。
3. **第 2 格｜AI 統整：** 播放統整過程（事先做好的結果）→「開始確認」。
4. **第 3 格｜資深確認：** 小橘一次問一項，共 12 項（4 張批次卡＋8 題）。
   - 可以按「帶入示範答案」快速帶過。
   - 12 項都確認完，「產生主管版 SOP」才會打開。
5. **主管版 SOP：** 按「產生主管版 SOP」後，這一版就是目前版本，新人登入就會看到。可以搜尋、點分類標籤、匯出 Word。
6. **新人登入：** 進入新人版 SOP，依分類閱讀。
   - 閱讀進度會記錄下來。
   - 頁尾可以勾「閱讀時間加速 10 倍」，簡報時用。
7. **重新示範：** 登入頁頁尾的「重設示範（回到第一次使用）」按兩次，就會回到第一次使用的狀態。

**示範注意**

- 主管和新人要在同一台電腦、同一個瀏覽器示範，先主管、後新人。
- 主管產生的版本只存在這個瀏覽器裡（見「九、目前限制」）。

## 四、資料規則（很重要）

1. **`03_統整模擬資料包_v3` 是全組共用的標準資料，請不要修改。**
   - 已和 v3 壓縮檔逐檔比對，24 個檔案完全相同。
   - 後續的問答、測驗、評分都用同一份資料。
2. **網頁不直接讀 JSON 檔。** 直接雙擊開網頁時，瀏覽器不允許讀電腦裡的 JSON，所以改用 `tools/make_data.py` 把 JSON 轉成兩個資料檔：
   - `data/demo_data.js`：網頁目前用的資料，全域變數 `DATA`。
   - `data/v3_all.js`：5 個 JSON 原封不動包在一起，全域變數 `V3`，給問答、測驗、評分用。
3. **隨時可以檢查網頁資料有沒有被改到：** 在 `02_網頁原始碼` 裡執行 `python tools/make_data.py --check`。目前結果是「網頁資料與 v3 JSON 完全一致」。
4. **主管照示範答案確認時，產生的 SOP 和 `sop_latest.json` 完全相同。**
   - 主管在網頁上選了不同答案，只會改畫面上那一條，並標「依資深選擇修改」。
   - 原始 JSON 不會被改。
5. **之後真的串 AI 時，內容才會不一樣；目前資料一律不動。**
6. `03` 裡的 `07_統整中心示範網頁` 是舊版示範網頁，已經由 `01_網頁成品` 取代。為了讓資料包保持原樣，舊版沒有刪掉。

## 五、程式結構

**基本狀況**

- 純前端（HTML＋CSS＋JavaScript），不用安裝，也沒有後端。
- 沒有串 AI：AI 統整結果是事先做好的，從 v3 JSON 播放。
- 需要網路的只有兩個：
  - Google Fonts：粉圓體、思源黑體。
  - jsDelivr 的 `docx@8.5.0`：在瀏覽器裡產生 Word。
- 沒有網路時畫面照樣能用，但字型會變成電腦內建字型，也不能匯出 Word。

| 檔案 | 做什麼 |
|---|---|
| `index.html` | 入口：載入樣式、資料和程式，**順序不能亂** |
| `css/style.css` | 經驗柑仔店視覺：顏色和字體設定、按鈕、區塊、小橘、進度路、分類標籤 |
| `js/sopdoc.js` | SOP 文件：`sopModel()` 整理內容，`sopDocHTML()` 產生網頁畫面，`sopDocxBlob()` 產生 Word，所以**網頁上看到的＝匯出的 Word** |
| `js/core.js` | 共用小工具、示範帳號、小橘繪圖 `xiaoju()`、對話泡泡 `bubble()`、`toast()` |
| `js/app.js` | 狀態 `S`、登入頁、版面 `shell()`、**頁面與導覽列登記 `PAGES`／`NAV`**、匯出 Word |
| `js/manager.js` | 主管：小橘帶路進度路、第 1～3 格、主管版 SOP |
| `js/newbie.js` | 新人：新人版 SOP、閱讀進度（依字數估時間） |
| `js/main.js` | 啟動，最後載入 |
| `data/demo_data.js`、`data/v3_all.js` | 由 v3 JSON 轉出，**不要手改** |
| `tools/make_data.py` | 從 v3 JSON 重新產生 data/，`--check` 只檢查不寫檔 |
| `tools/build.py` | 把多個檔合成單一 HTML（`dist/SOP統整中心.html`） |
| `tools/test_flow.py` | 自動跑完整流程，共 17 項檢查（選用） |

**載入順序：** docx → data → sopdoc.js → core.js → app.js → manager.js → newbie.js →（組員的頁面檔）→ main.js

## 六、新增頁面（把問答、測驗、評分接進來）

每個頁面只要做三件事：

1. 在 `PAGES` 登記頁面。
2. 在 `NAV` 加一顆按鈕。
3. 寫一個畫面函式。

這個做法已經實測可以運作。

**步驟 1：新增 `js/quiz.js`（以新人的小測驗為例）**

```js
PAGES.quiz = {role: "newbie", render: () => vQuiz()};   // role："newbie" 或 "manager"
NAV.newbie.push({to: "quiz", label: "小測驗"});          // 新人頂欄多一顆按鈕

function vQuiz(){
  const reds = V3.sop_latest.rules.filter(r => r.red_line);   // 用 v3 資料出題
  shell("", `<section class="xk-panel one flip">
    <div class="phead"><div class="ttl"><span class="xk-cap">小測驗</span><h2>紅線 ${reds.length} 條</h2></div></div>
    <div class="pbody stack">${bubble("先從紅線開始，答錯沒關係。", {expr: "hint"})}
      <!-- 題目放這裡 -->
    </div>
  </section>`);
  wireCats();   // 讓小橘點了會跳一下
}
```

**步驟 2：修改 `index.html`**

- 在 `js/main.js` 前面加一行 `<script src="js/quiz.js"></script>`。
- 要用 `V3` 的話，把 `data/v3_all.js` 那一行的註解拿掉。

**做完的結果**

- 新人頂欄會自動出現「新人版 SOP｜小測驗」。導覽列只在有兩顆以上按鈕時才出現，所以新人目前沒有導覽列。
- 主管要新增頁面，就用 `role: "manager"` 和 `NAV.manager`。
- 不同身分不能進對方的頁面，會自動回到自己的首頁。

**想加條件鎖住某一頁時**

- 加 `locked: () => 條件`，例如：新人沒讀完 SOP 前不能測驗。
- 條件成立時，頂欄按鈕會變灰並加鎖頭，跟主管版 SOP 第一次使用時一樣。

**可以直接用的共用工具**

| 工具 | 用途 |
|---|---|
| `shell(上方, 內容, 頁尾加註)` | 畫出頂欄＋頁面。上方放進度路之類，沒有就給 `""` |
| `bubble(文字, {expr, who})` | 小橘對話泡泡 |
| `xiaoju({expr, gear, label})` | 單獨畫小橘（SVG）。expr：`default`、`happy`、`hint`、`confused`；gear：`senior`（主管領巾）、`rookie`（新人名牌） |
| `wireCats(台詞陣列)` | 點小橘會跳一下，並輪流說台詞 |
| `toast(訊息)` | 畫面下方的短暫提示 |
| `store.get(key)`／`store.set(key, 值)` | 存取瀏覽器資料，失敗也不會壞掉 |
| `esc(文字)` | 放進畫面前一定要先處理，避免特殊字元出錯 |
| `toTop()` | 回到頁面頂端 |
| `sopModel(mode, doc)`、`sopDocHTML(...)`、`sopDocxBlob(...)`、`exportDocx(mode, doc)` | SOP 內容、畫面、Word。mode：`"senior"` 或 `"newbie"` |

**樣式規則（維持經驗柑仔店風格）**

- **版面：**
  - 一頁一個區塊：`xk-panel one`，上面是 `phead`（標題列），下面是 `pbody`（內容）。
  - 標題列用 `ttl`：格子標籤 `xk-cap`＋20px 標題 `h2`。
  - 畫面不凍結，整頁一起捲動。
- **按鈕：**
  - 主要按鈕 `xk-btn`：鵝黃底、粗框、貼紙陰影，一個區塊只放一顆。
  - 次要按鈕 `xk-btn-ghost`：白底、陶土紅框。
  - 按鈕文字以動詞開頭，要前往下一步的加「›」。
- **狀態標籤 `chip`：** 有 `todo`、`doing`、`done`、`warn` 四種，一定要「文字＋符號」，例如「✓ 已完成」「! 還有 3 項」。
- **分類標籤：** 用 `tabs` 和 `tab`。
- **小橘：**
  - 只出現在對話泡泡和進度路上，不做飄在畫面上的小橘。
  - 每則話最多一個「喵」，不用 emoji。
- **設計系統：** 視覺沿用小組的 Design System v2（原名「巷口服務所」，網頁已改名為經驗柑仔店）。目前只沿用它的視覺風格，規則和等級設定之後再調整。

## 七、頁面之間共用的資料

| 名稱 | 放在哪裡 | 內容 |
|---|---|---|
| `DATA` | `data/demo_data.js` | 網頁目前用的資料（由 v3 JSON 轉出） |
| `V3` | `data/v3_all.js` | 5 個 JSON 原樣：`V3.sop_latest`、`V3.sop_history`、`V3.review`、`V3.qa_cases`、`V3.settings` |
| `S.user` | 記憶體 | 目前登入者：`{key: "manager" 或 "newbie", id, name, title, role}` |
| `S.pub`、`hasPub()` | 瀏覽器 localStorage：`knowhow-sop-published` | 主管產生的目前版本：`{version, at, by, rules, pending, decisions}`。rules 的欄位和 `DATA.rules` 相同，另外多了 `pending`、`byYou` |
| 新人閱讀進度 | localStorage：`knowhow-read-帳號-版本-時間` | `{分類代號: 已讀秒數}`。分類代號：`steps`、`red`、`ch1`～`ch9`、`tools` |

**建議的資料對應**

- **新人問答：**
  - 主要用 `V3.qa_cases`，共 6 個情境，每個情境的欄位：
    - `newbie_asks`：新人問的話
    - `check_latest`、`check_history`：先查最新版、再查歷史版
    - `outcome`：查詢結果
    - `ai_should_reply`：AI 應該怎麼回
    - `source_chip`：回覆上標示的出處
    - `writes_pending`：要不要記到待補
  - 搭配 `V3.sop_latest`、`V3.sop_history` 查規則。
  - 查不到的問題寫入待補，格式見 `V3.sop_history.pending_format`。
- **測驗：**
  - 用 `V3.sop_latest.rules`。其中 `red_line` 為 true 的 12 條是紅線，建議先出。
  - 用 `no` 編號可以對回 SOP 的哪一步、第幾條。
  - 只用新人版看得到的內容出題，不要用「和舊檔不同」「已失效」。
- **評分：**
  - 可以合併上面的閱讀進度和測驗結果。
  - 新增的存檔 key 請用 `knowhow-` 開頭，登入頁的「重設示範」才會一起清掉。

## 九、目前限制，以及正式版要做的事

- **示範登入不檢查密碼。**
  - 正式版要由後端驗證帳號。
  - 權限也要在後端擋：前端把按鈕藏起來，不等於真的鎖住。
- **資料只存在同一台電腦的瀏覽器裡（localStorage）**，包括主管產生的版本和新人的閱讀進度。正式版要改存資料庫。
- **沒有串 AI。** 要串的話，接在三個地方：
  1. 第 2 格：讀檔 → 清洗 → 拆規則
  2. 第 3 格：產生要資深確認的題目
  3. 新人問答
  - API 金鑰不能放在前端或 GitHub，要透過後端呼叫。
- **匯入自己的檔案時，目前只會列出檔名**，統整結果仍然是好物集的示範資料。

## 十、這版網頁的設計決定（11/17 與組員討論後）

**名稱**

- 網頁名稱定為「經驗柑仔店」，英文 Know-how Corner Store：資深把經驗擺上架，新人隨時來拿。
- 網頁給各企業通用，畫面上不寫「電商客服」；好物集的電商客服只是範例資料。

**登入與權限**

- 主管、新人分開登入，各自只看得到自己的介面。
- 新人看不到主管的內容：本次確認、待補、和舊檔不同、已失效、生效日和依據。新人也看不到版本時間和確認主管的名字。

**主管流程**

- 第一次使用時，「主管版 SOP」鎖住，主管完成第一次統整才打開。
- 12 項全部確認完，才能產生主管版 SOP。
- 產生就等於發布，沒有另外的「發布給新人」按鈕。
- 可以點或拖曳進度路回到前面的格子；中途切到別頁再回來，會接著做。

**匯出**

- 只匯出 Word，檔名和內容都不寫時間。
- 新人版的 Word 不寫確認人。

**版面**

- 所有頁面都不凍結，整頁一起捲動，一頁一個區塊。
- 新人閱讀進度依字數估算時間，但畫面上不寫每一格要讀幾分鐘。
